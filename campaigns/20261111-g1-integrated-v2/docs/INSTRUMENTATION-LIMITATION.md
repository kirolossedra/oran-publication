# Superseded packet-event interpretation

The 160-cell `20261111-g1-integrated` run root and the derived packet-event summaries are retained as historical evidence, but **their packet-level delivery, loss, and latency values must not be used as findings**. The first instrumentation revision attached observation IDs as ns-3 `PacketTag`s. Under NR packet aggregation/reassembly, those simulator-only tags were copied to multiple received application packets. In one light-load run, each UE/direction had 109 TX events and 109 RX events, but only 82–88 distinct RX sequence values; the app KPI independently reported 100% aggregate PDR. The event-derived per-packet identity was therefore invalid.

The correction replaces the tag with an 18-byte serialized header carried in each UDP datagram. The receiver removes the header before storing/counting the original application payload. A matched validation run (`simulator/runs/20261111-g1-integrated-v2-diagnostic/`) showed, for all six UEs and both directions, 109 TX sequences, 109 distinct RX sequences, zero duplicate RX sequences, and zero missing sequences. The full corrected matrix is being rerun under `simulator/runs/20261111-g1-integrated-v2/`; its derived analyses will be written to `results/20261111-g1-integrated-v2/`.

Other v1 streams, including applied MAC grants, MAC demand snapshots, and logged channel-state/position observations, remain preserved and may be audited for engineering diagnostics, but no v1 performance comparison is treated as the final result. The v2 packet header adds 18 bytes of metadata to each UDP datagram; packet-event payload byte counts exclude this measurement header, while the NR radio carries it.
